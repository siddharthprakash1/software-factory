I read `src/surety/calib/metrics.py` and `tests/test_metrics.py`. The three items are independent and small:

1. **Empty input.** Every row-averaging metric uses `np.mean` on a list or array, so empty input gives NaN plus a `RuntimeWarning`. That covers `accuracy`, `brier`, `confident_error_rate`, `coverage`, `mean_set_size`, `automation_rate`, and `autonomous_error_rate`. `wilson` already returns `(0.0, 1.0)` for `n=0`, and `risk_coverage_curve` already guards its empty case. `ece` does not warn: it returns `0.0` on empty input, because its bin loop never runs. Whether `ece` should return NaN for consistency is a one-line decision for the implementer to make and note.
2. **ECE tests.** The `p_max == 1.0` clamp (`np.minimum(..., n_bins - 1)`) is real and untested, and no test sums more than one non-empty bin. Both need pinned values. These should be computed by hand, not copied from the code's output, so the tests check the formula.
3. **Test split.** `test_autonomous_error_counts_only_singletons` asserts both `automation_rate` and `autonomous_error_rate`. Splitting it is mechanical.

The fix is a small `_mean` helper or explicit empty-guards in `metrics.py`, plus new and split tests in `tests/test_metrics.py`. Non-empty outputs are unchanged, so no reported number moves. I did not run the tests, since this was a read-only triage.
